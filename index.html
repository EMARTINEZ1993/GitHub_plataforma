¿Qué es Git?

Git es un sistema de control de versiones distribuido de código abierto. Se ejecuta de forma 100% local en tu disco duro para rastrear cambios en el código sin requerir conexión a internet.

  • check Historial completo e inmutable guardado en la carpeta oculta .git.
  • check Creación ágil de ramas (branches) para experimentar sin riesgos.
  • check Manejo de estados: Working Directory, Staging y Repository.
$ git --version // Local CLI
PLATAFORMA CLOUD cloud

¿Qué es GitHub?

GitHub es una plataforma de alojamiento en la nube construida sobre Git. Facilita la colaboración en equipo, respaldo remoto, revisión de código mediante Pull Requests y portafolio profesional.

  • check Servidor centralizado accesible vía HTTPS o llaves SSH.
  • check Gestión de Issues, Pull Requests, Automatizaciones CI/CD (GitHub Actions).
  • check Visibilidad de repositorios: Públicos o Privados para tu equipo.
URL: https://github.com/usuario/mi-repo.git

Analogía Esencial

Git es como:

El motor de tu automóvil o una cámara de fotos local. Funciona donde sea, contigo, sin conexión a internet.

GitHub es como:

Instagram o Google Drive. El lugar público o compartido donde subes las fotos para que otros las vean o colaboren.

El Git Push:

El camión de transporte que sincroniza los paquetes desde tu máquina local hacia el almacén en la nube.

¿La cuenta mostrada NO es la tuya? Desvincula con `unset`

Si ves el nombre de otro estudiante o colega, elimina la identidad registrada con los comandos de desvinculación antes de crear nuevos repositorios:

$ git config --global --unset user.name
$ git config --global --unset user.email

Configurar tu Propia Cuenta y Autoría

Ejecuta los siguientes comandos en tu terminal reemplazando con tus datos reales de GitHub:

2. Registrar tu Correo de GitHub

code calcularSalario.py 
# calcularSalario.py
# Práctica de Control de Versiones con Git y GitHub

def calcular_salario(horas, valor_hora):
    salario_bruto = horas * valor_hora
    # Deducciones de salud y pension (8% total)
    deducciones = salario_bruto * 0.08
    salario_neto = salario_bruto - deducciones
    return salario_bruto, deducciones, salario_neto

def main():
    print("=== SISTEMA DE CALCULO SALARIAL ===")
    try:
        horas = float(input("Ingrese horas trabajadas: "))
        tarifa = float(input("Ingrese valor por hora: "))
        
        bruto, deduccion, neto = calcular_salario(horas, tarifa)
        
        print(f"\nSalario Bruto:     ${bruto:,.2f}")
        print(f"Deducciones (8%):  ${deduccion:,.2f}")
        print(f"Total a Pagar:     ${neto:,.2f}")
    except ValueError:
        print("Error: Ingresa valores numericos validos.")

if __name__ == "__main__":
    main()

Inicialización del Repositorio Local

El comando git init crea el almacén de control de versiones dentro de tu carpeta de trabajo.

Paso 1: Inicializar
$ git init
Initialized empty Git repository in C:/.../introduccion_git/.git/
Paso 2: Consultar Estado
$ git status
Untracked files:
  README.md
  calcularSalario.py

¿Qué sucede tras ejecutar git init?

Carpeta .git Es una carpeta oculta que contiene el árbol de objetos binarios e índices. ¡Nunca la borres!
Puntero HEAD Apunta a la rama en la que estás situado actualmente para registrar los próximos commits.
Estado Untracked Git ve tus archivos pero no los está rastreando hasta que los añadas con git add.

Los Tres Estados de Git: Staging & Commit

En Git los cambios no se guardan de golpe: primero los preparas en el Staging Area con git add y luego los confirmas con git commit.

folder_open
1. Working Directory

Tus archivos en el disco con modificaciones pendientes.

inventory_2
2. Staging Area

La "caja" de cambios listos que formarán parte del commit.

task_alt
3. Repository (.git)

Instantánea guardada de forma permanente con código SHA-1.

Paso A: Añadir al Staging
$ git add .

El punto (.) indica añadir todos los archivos de la carpeta actual.

Paso B: Guardar Commit
$ git commit -m "feat: estructura inicial con calcularSalario y README"

El mensaje con -m debe describir con precisión qué se agregó.

Vincular tu Repositorio Local con GitHub

Ingresa tu nombre de usuario exacto de GitHub para generar los comandos con tu URL personalizada:

2. Vincular el Servidor Remoto (origin)
$ git remote add origin https://github.com/mi-usuario/introduccion_git.git

Troubleshooting: Solución a los 8 Errores Más Frecuentes

Haz clic en cualquier error para desplegar su causa exacta y cómo resolverlo de inmediato en tu consola:

Causa: Git no está en la variable PATH de Windows o tu terminal estaba abierta antes de instalar Git.

Solución: Cierra y vuelve a abrir Visual Studio Code. Si persiste, reinstala Git marcando la opción "Add Git to PATH".

Causa: El Administrador de Credenciales de Windows guardó el login de otro usuario anterior en ese equipo compartido.

Solución: Ve a Inicio > Administrador de Credenciales > Credenciales de Windows y elimina la entrada git:https://github.com.

Causa: Ya agregaste un origen remoto con ese alias en un intento previo.

Solución: Actualízalo corriendo: git remote set-url origin https://github.com/TU_USUARIO/introduccion_git.git o bórralo con git remote remove origin.

Causa: Creaste el repositorio en GitHub con un README o licencia, por lo que el remoto tiene commits que no existen en tu disco local.

Solución: Ejecuta git pull origin main --allow-unrelated-histories, resuelve cualquier conflicto de texto y vuelve a hacer push.

Causa: Tu terminal está ubicada en otra carpeta o nunca ejecutaste git init en esa ruta.

Solución: Revisa tu carpeta activa con pwd o cd introduccion_git y luego corre git init.

Causa: Intentaste hacer commit sin haber registrado tu nombre ni tu correo en Git.

Solución: Corre git config --global user.name "Tu Nombre" y git config --global user.email "tu_email@ejemplo.com".

Causa: GitHub exige OAuth o un Personal Access Token (PAT) en vez de tu contraseña normal.

Solución: Inicia sesión con la ventana emergente de VS Code o genera un Token en GitHub > Settings > Developer Settings > Personal access tokens con permiso de repo.

Causa: Intentaste hacer git push origin main sin haber realizado ningún commit primero.

Solución: Haz git add . y luego git commit -m "primer commit" antes de empujar los cambios.
